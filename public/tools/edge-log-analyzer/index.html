Ghost Fact Annotations (GFA) no file loaded

GFA is the namespace=//provider/field/field/… column some edge features write to explain a decision (why a request was classified, challenged or skipped). The column is found automatically; each annotation is split into provider entries and every field is tallied, so you can see which providers fired, which values dominate, and jump to the exact lines. Field names, value meanings and the Insights list come from a GFA dictionary (JSON) you load from your own disk — it stays in this browser's local storage, is never uploaded, and isn't part of this page. Without one you still get the structure: providers, field positions and raw values. Click "fields" on a provider to break it down; use Trace to follow one value (e.g. a session ID) across every annotation.

Custom Query no file loaded

Describe what you want in plain English — this runs entirely in your browser via a small pattern-matcher (no AI, no API calls, nothing leaves your machine). It recognizes every documented r-line and f-line column by name (e.g. "object status information", "turnaround time", "forward hostname") or by number ("field 16", "column 24"), and shows you the exact AWK command it built, which you can edit directly below. Mention "f line" / "origin leg" / "upstream" to query origin/forward-leg records instead of client-facing ones. Full column reference: download the field list (PDF).

Advanced: write AWK + pipeline directly

Supports $1…$N, $0, $NF, NR, NF, == != ~ !~ < <= > >= && || !, string concatenation, and print (no arithmetic or variables). Pipe into sort [-n -r -u], uniq [-c], head/tail [-N | -n N], grep [-v -i -E -F -c] PATTERN, or wc -l; any other option is rejected rather than silently ignored. Queries run over the lines that passed parsing, in the current time range. Field numbers follow the documented r-line / f-line column layout (1-indexed) — e.g. on r-lines $14=status, $15=error reason, $16=object status information; on S records (client-facing, compact layout) $16=status, $32=error reason, $18=object status, $31=path after the host; on f-lines $11=forward IP, $15=status, $24=forward hostname, $30=error. A program can hold several pattern {print …} rules, e.g. one per record type.
